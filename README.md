# Collar Health Shiny App

MoveApps

Github repository: *github.com/sitkensis22/Collar-Health-Shiny-App* (*https://github.com/sitkensis22/Collar-Health-Shiny-App*)

## Description
Provides visualization tools for alerts generated by Collar-Health-Alert-App (and possibly filtered by Collar-Health-Filter-App) including Leaflet map, individual and all tabular data, and alert-specific plots. The user can (1) select data to view by individual and filter by those with or without alerts; (2) select alert events; (3) select one of 6 basemaps; (4) filter data by date or number of locations; (5) remove individuals from the dataset; (6) link to the individual's Movebank deployment page; (7) download individual data, all data, or a an individual report that contains summary, map, and location data; (8) and select which data fields to display in individual data table.  

## Documentation
This App creates a Shiny UI that allows the interactive visualization of move2 location data in map, graphical, and tabular form. The App is meant to work in conjunction in a workflow with the Collar-Health-Alert-App (and possibly filtered by Collar-Health-Filter-App) and uses the move2 dataset with fields appended for each alert type: `mortality`, `cluster`, `nsd`, `voltage`, `gps_accuracy`, `gps_transmission`, and `gps_resurrection`, and the number of unique alerts per individual, `nAlerts`. The App will not work without these fields appended to the dataset. The alerts are binary fields (0/1) indicating which locations meet the one of 7 alert criteria, and these locations are displayed in orange color on the Leaflet map. The start and end of the movement track are colored green and red, respectively, on the Leaflet map. The user can select individuals by clicking on the "Track information" table, the "All data" table, or in the "Select individual" dropdown menu. The "Select alert" dropdown menu will automatically update as different individuals are selected, as will the date range, number of locations, "Individual data" table, and Event plots. The Leaflet map locations will show the datetime when the user hovers over the points, and tooltips will also be displayed on the Event plots as the user hovers over the points. Note that the "device_id" field is the `tag_local_identifier` (or `serial_no`) field in the track data.

### Application scope
#### Generality of App usability
This app was developed for any taxinomic group.  

#### Required data properties
The App should work for any kind of (location) data. However, the App is only meant to work in conjunction with the Collar Health Alert App in a previous step of workflow.

### Input type
`move2::move2_loc`

### Output type
`move2::move2_loc`

### Artefacts
None.

The Download button enables a local download of the "All data" table (as a .csv file), "Individual data" table (as a .csv file), or collar health report (as an HTML file) depending on the `Select data` input. 

### Settings 
**Select individual (`individual_select`):** Select the individual based on the track id column in the move2 dataset. Note that the individual can also be selected by clicking on "Track information" or "All data" table rows.

**Alert toggle (`alert_toggle`):** This switch filters the individuals in the data based on if they have any alerts or not. 

**Select alert (`notification_type`):** Select the alert to display in the Leaflet map, "Individual data" table, and Event plot tabs. Note that this dropdown menu will automatically update based on the selected individual.  


`Store settings`: click to store the current settings of the App for future Workflow runs. 

### Changes in output data
The input data remains unchanged.
